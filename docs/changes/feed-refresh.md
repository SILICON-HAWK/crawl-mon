# Background feed refresh

Added an explicitly approved CLI worker for five configured feeds. It uses the existing Crawlee engine, filesystem run records, evidence and extraction; runs one source at a time, one page per run, at least 60 seconds between source starts, at least 12 hours between successful source attempts and 24 hours after failures or interrupted attempts. The scheduled engine applies a two-second minimum request interval, robots allow/disallow and integer crawl-delay when larger, with no immediate retries. A per-data-root advisory lock prevents duplicate scheduler processes and atomic state files retain deadlines across restarts. CLI `--status` checks the lock and `--stop` requests graceful shutdown.

Limits: this is a session-bound CLI process, not a service or shared distributed queue. Other manual crawls do not share this rate budget. It does not automatically classify jobs or prune snapshots; retained data grows. Robots directives can change and unsupported non-integer delay formats are not interpreted. It does not impose a byte-size limit on remote responses. If the application data root is busy, that scheduled attempt fails safely and uses the failure interval.

Verification: scheduled-mode controlled HTTP test checks the declared one-second robots delay; all 13 Crawlee adapter tests pass. Four schedule/CLI tests cover backoff, restart deadlines and lock-observed graceful stop without network. Live worker refreshed SonicWall successfully and the CLI status reported an active worker. Individual job posting verification and provider/LLM rate limits are separate.
